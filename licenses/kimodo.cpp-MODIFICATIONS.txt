Modifications made by the CAGE project (Apache-2.0 section 4(b)). In summary:
  - the build uses the caller's ggml target when one already exists,
    instead of building the pinned ggml submodule. CAGE links kimodo into
    a shared object that already contains one ggml (llama.cpp/mtmd,
    sd.cpp, trellis.cpp, audio.cpp all share it); a second copy would
    carry its own backend registry, CUDA context and VRAM accounting.
    Sources include ggml-backend.h / ggml.h, which that ggml provides,
    instead of ggml-cpu.h / gguf.h;
  - backends and devices are chosen through the ggml registry (no longer
    a fixed Vulkan device 0), device strings may name several devices,
    and a wrong device is reported at load time.
No algorithm was changed. Every file changed relative to upstream is listed below.
